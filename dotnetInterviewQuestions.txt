Boxing and Unboxing - Boxing is converting value types (int, struct..) to reference types.
	Boxing is implicit, unboxing is explicit
	Unboxing - extracts the value type from the object
	
	int i = 123;

	object o = i;
	
	o = 123;
	i = (int)o;  // unboxing

Reference Types vs Value Types

Value Types are stored on the stack
Reference Type values are stored on the heap

Key Differences: Stack vs. Heap
Feature 	Stack	Heap
Data Stored	Value types (int, bool, struct), and pointers/references to heap objects.	Reference types (class, object, string, array).
Allocation	Automatic and very fast (LIFO: Last-In, First-Out).	Dynamic and slower, requires searching for available space.
Deallocation	Automatic when the method/scope ends (stack frame is popped).	Managed by the Garbage Collector (GC) when no longer referenced.
Size Limit	Fixed and limited (typically ~1MB per thread), can cause a StackOverflowException.	Dynamically growing, limited by physical memory.
Access Speed	Very fast, as memory is accessed sequentially and is often CPU cache-friendly.	Slower due to indirection (access via reference/pointer) and potential memory fragmentation.
Lifetime	Tied to the scope of the function/method where declared.	Persists as long as there is an active reference pointing to it.
Thread Safety	Inherently thread-safe; each thread has its own private stack.	Not inherently thread-safe; shared memory requires careful management when accessed by multiple threads.

Basics
	Abstract Class vs Interface
		a class can implement multiple interfaces but inherit only a single abstract class, and abstract classes can maintain state (fields and constructors), 
		whereas interfaces (before C# 8.0) could not and still cannot have instance fields
		
When we talk about abstract classes we are defining characteristics of an object type; specifying what an object is.
When we talk about an interface and define capabilities that we promise to provide, we are talking about establishing a contract about what the object can do.

Program.cs or Startup.cs
In older versions of ASP.NET Core (pre-.NET 6), Program.cs was the application's entry point, while Startup.cs was a separate file responsible for configuration. 
In modern .NET (6+), the functionalities of both files are typically consolidated into a single, streamlined Program.cs file using top-level statements.
